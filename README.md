# Living Blueprint

Living Blueprint is a portable, AI-agnostic body of working knowledge and practice.

Its purpose is to help people and AI systems work from evidence, observed reality, useful feedback, and explicit boundaries rather than unnecessary speculative complexity.

Living Blueprint is intended to guide how work is performed. It does not replace human judgment, project requirements, domain expertise, or the authority of the project owner.

## Status

This repository contains the retained knowledge and practical working principles extracted from the Living Blueprint project.

Living Blueprint is not presented as a universal methodology, framework, or claim of novelty.

Its value is determined by whether it helps real work produce better, clearer, or more reliable results.

## Core working direction

For work that can be developed and tested through execution, prefer:

    MINIMUM REQUIREMENT
            ↓
          BUILD
            ↓
           RUN
            ↓
         OBSERVE
            ↓
        REAL GAP
            ↓
     RESEARCH / ANALYZE
            ↓
          CHANGE
            ↓
         RUN AGAIN

The loop is a default working direction, not a rigid sequence.

Research should be driven by a real question, problem, or observed gap whenever possible.

Do not add complexity merely because a capability might be useful in the future.

## How Living Blueprint should affect work

When following Living Blueprint, a person or AI should:

- understand the actual task and its boundaries before acting;
- distinguish what is known from what is uncertain;
- prefer evidence over unsupported assumptions;
- start with the smallest useful approach when practical;
- run or test the work when execution is possible;
- use observed results to identify real gaps;
- research when the evidence or problem requires it;
- make changes that address the identified problem;
- verify the result again;
- preserve meaningful uncertainty rather than silently turning it into certainty;
- treat counter-evidence and negative results as useful information;
- stop or change direction when the evidence no longer justifies further work.

Living Blueprint does not require blind compliance. Context, evidence, technical constraints, and project authority remain important.

## Using Living Blueprint

A project can adopt these working rules by referring to this repository.

The canonical rules are maintained in:

- `CORE.md` — core principles
- `PRACTICE.md` — practical working loop
- `UNKNOWN.md` — handling uncertainty and stopping conditions
- `HISTORY.md` — history and evolution

Adapters for particular AI agents or tools may point to these canonical documents without becoming separate sources of truth.

## Design goals

- AI-agnostic
- Human-readable
- Machine-readable
- Portable
- Versioned
- Evidence-oriented
- Practical
- Minimal
- Evolvable through real-world feedback

The repository should remain as small as possible while remaining useful.

## Evolution

Living Blueprint should evolve from actual use.

A missing capability should normally be added because real work demonstrates a need for it, not merely because the capability might be useful someday.

Changes should preserve the distinction between established knowledge, practical guidance, uncertainty, and historical context.
